
* Understanding of the embeddings inside the Transformer

** Token embeddings:
Token embeddings are of shape [vocab_size, d_model]. They are randomly initialized at first and learned during the training process. We can imagine the embedding matrix as a high-dimensional vector space that contains all the vocabulary we want the model to learn from.

** Positional encoding:
Taking the original Transformer as an example, it used sinusoidal positional encoding, which was fixed during training. The position is determined by sine and cosine functions according to the position index, storing them in a higher-dimensional space.

*** Understanding the execution of our code in the Kernel

The computation happens in parallel. We have group of blocks known as the grid and inside of block there may be multiple threads.

#+BEGIN_SRC C
  int row = blockIdx.x;
  int col = blockIdx.y;
#+END_SRC

The above code gives us the row and col of a 1D kernel launch. The thread Id in the kernel is given by

#+BEGIN_SRC C
int e = threadIdx.x;
#+END_SRC

Now what we are trying to do is create a lookup. It tricks me because I am not used to think in termms of the GPU.

#+BEGIN_SRC C
int token_id = A[row * gridDim.y + e];
#+END_SRC

In our model the shape of A is seq_len x batch_size.

That gridDim.y is the same as batch_size

So we need to keep in mind that our memory is flat, which it is in the hardware level.

Imagine a case where we are in position(0, 0)

A[0 * 3 + 0] = A[0] = 0
B[0 * 6 + 0] = B[0] = 1.0


Now lets go to the case wwhere we are in position(0, 0) in the gird but thread id is 1;

A[0 * 3 + 0] = A[0] = 0
B[0 * 6 + 1] = B[1] = 2.0f
